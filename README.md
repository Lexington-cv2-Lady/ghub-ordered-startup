# G HUB 有序启动

解决 Logitech G HUB 一个长期未修复的**启动顺序 bug**。

---

## 这个工具解决什么问题

G HUB 由多个进程组成，其中两个关键进程必须按特定顺序启动：

```
lghub_agent.exe  →  lghub_updater.exe  →  lghub.exe
```

**如果 `updater` 比 `agent` 先启动，G HUB 会卡在启动界面无法使用。**

这个 bug 是**概率性**的——有时正常、有时卡死，所以很多人会误以为是软件损坏，
反复卸载重装却始终不解决问题。

本工具在启动前先停掉 Updater 服务、杀光所有残留进程，
再严格按上述顺序重新拉起，并**校验实际启动顺序**。

## 快速开始

1. **解压**到一个固定目录（不要直接在压缩包里运行）。
2. 双击 **`Start-GHUB.cmd`**。
3. 首次运行会：
   - 弹出 UAC 请求管理员权限 → 点「是」
   - 询问是否**创建/替换桌面快捷方式**（替换前自动备份原图标）
   - 询问是否**设置开机自启**（之后可用 `Autostart-Settings.cmd` 随时更改）
4. 日常使用：双击桌面图标即可。

## 文件说明

| 文件 | 作用 |
|---|---|
| `Start-GHUB.cmd` | **主入口**，双击它按正确顺序启动 G HUB |
| `start_lghub_universal.ps1` | 主逻辑（由上面的 cmd 调用）|
| `Autostart-Settings.cmd` | 独立开关菜单：开启/关闭开机自启 |
| `ghub_autostart.ps1` | 自启逻辑（由上面的 cmd 调用）|
| `README.txt` | 详细使用说明与常见问题 |

## 两种启动模式

| 场景 | 行为 |
|---|---|
| **双击桌面图标 / `Start-GHUB.cmd`** | 正常启动，G HUB 主窗口会打开 |
| **开机自启**（计划任务，带 `-Silent`）| **静默启动**：只驻留系统托盘，不弹窗口；需要时点托盘图标即可打开主界面 |

静默模式通过 `lghub_system_tray.exe --minimized` 实现，与 G HUB 自带的开机自启行为一致，
但额外保证了 Agent → Updater 的正确启动顺序。

## 特性

- **自动探测安装路径** — 默认位置 → 卸载注册表项 → 显示名模糊匹配，不写死路径与版本
- **组件自适应** — 未检测到 `lghub_agent.exe` 时（新版可能已合并组件）自动退回普通启动
- **失败不武断** — 顺序校验不通过时会提示「先试一下，能用就忽略，不能用按 1 重跑」，判断权交给用户
- **不污染系统** — 只做「停服务 / 杀进程 / 按顺序启动」，不碰配置、注册表、板载内存
- **不干扰自动更新** — 运行时既不读取也不写入更新配置文件

> ⚠️ **不要**用防火墙封禁 `lghub_updater.exe` 或更新服务器来阻止更新。
> 该组件同时负责按需下载设备资源，封掉会导致 G HUB 卡在「正在加载资源」。
> 想关自动更新请用 G HUB 自带开关：设置 → 应用程序设置 → 取消勾选「启用自动更新」。

## 系统要求

- Windows 10 及以上
- PowerShell 5.1（系统自带）
- 需要管理员权限（用于停止服务与结束提权进程，脚本会自动请求提权）

## 已知限制

- 若 G HUB 安装在非常规路径且注册表无记录，可能探测失败（会给出明确提示）
- 脚本不修复 G HUB 自身的其他问题（安装失败、板载异常等），仅处理启动顺序
